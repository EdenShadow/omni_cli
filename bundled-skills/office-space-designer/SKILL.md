# 项目场景设计师

用户看到的空间一律称为“项目”，其中的人称为“成员”。技能 ID、office.json、officeAsset 等技术字段为兼容旧存档保留。遵循 [万物 AI 宿主契约](references/wanwu-app.md)；如果有 CREATION.md，先读当前任务输出路径和运行契约。

## 用格子搭建项目

默认采用清楚、有生活细节的像素游戏美术：正交格子地砖、阶梯状像素轮廓、平涂色块、简洁阴影。家具必须有可辨认的顶部与侧面厚度：桌面桌沿和桌腿、显示器机身侧面、沙发坐垫与扶手、书柜层板；墙体和地台也要表现厚度。用色块明暗、边缘高光与阶梯状接触阴影建立小模型般的体积感，避免纸片一样扁平。信息面板始终正面显示，只给边框加厚度与投影。不要调用 image2.5 或其他图片生成工具画整张场景；不要将参考图片直接铺成背景。

读 [格子与模块](references/map-art-and-regions.md)。以 `assets/pixel-project.json` 为起点，根据用户提示词改变配色、家具组合、位置、休闲区和装饰。森林图书馆、太空基地、海边小屋应有不同的视觉结果，不能只改名称。参考图片仅用于提取主题、色彩和布局意图。

输出可编辑的 office.json，宿主根据模块数据生成 background.svg。独立创作时可运行：

```sh
node <skill>/scripts/render-project-scene.mjs output/office.json output/background.svg
node <skill>/scripts/validate-office.mjs output/office.json
```

修改现有项目时保留模块 ID、项目数据、所有设备与成员身份。旧生图场景改为格子主题时保留原始文件供恢复，不改账号、设备、会话数据库。宿主对旧资产显示格子回退场景，不删除旧素材。

## 按提示词设计户型

人数、房间、玻璃或木质隔墙、门、横长或纵深等要求，先读 [户型与容量](references/floor-plans.md)。根据宿主已准备的户型母版继续设计，使用 floorPlan 房间与门洞数据，并校验入口到每间房和工位的路线。每间必须留门；30 人就预留至少 30 个互不重叠、可到达的工位。不能只画隔墙图案或在文字里承诺容量。房间名称、墙门材质、大小差异都需落实到数据。

默认保留当前地图宽度，优先向下扩展；明确要求加宽或确实放不下时才增加列数。100% 由宿主适配窗口宽度，三块顶部看板保持统一显示高度。外围隔墙可贴场景边缘，门仍通向内部公共走廊。房间名称仅存数据，不显示悬浮名称/材质标签，不生成烘焙在底图或家具上的名字、房间牌及路径拼字。

## 电脑设备外观再设计

普通会话里要求修改某台设备外观时，先用 wanwu-skills-sync 的 references/device-workflow.md 定位目标并准备创作，不要当作独立道具或整个办公室生成。执行设计的电脑与被修改外观的电脑可以不同。

当 CREATION.md 指定 DEVICE APPEARANCE 模式时，读 [设备外观](references/device-appearance.md)，只输出 `output/device.json` 和 `output/device.svg`。设计完整的设备造型，不强制带桌子：浮空 UFO、筋斗云、弹跳皮球上的电脑、机械臂都可以。默认静止；用户要求动态时使用 schemaVersion:2 的 animations.idle / animations.working 受控关键帧，支持屏幕文字滚动、公仔跳跃、浮空摆动及办公状态切换。按提示词保留造型与主题细节。已有设备素材是可编辑母版；这是项目内视觉外观，不添加真实设备，不改变设备身份、名字、会话、位置或硬件配置。生成后由宿主预览，用户应用后实时共享，可恢复默认。

## 单件道具创作

当 CREATION.md 指定 SINGLE PROP 模式时，只输出 `output/prop.json` 与 `output/prop.svg`，不输出整张项目。先读 SCENE_CONTEXT.json 的配色与家具尺度，结合提示词和参考图设计一件可辨认的家具或装饰。

prop.json 使用 `{"schemaVersion":1,"kind":"prop","name":"道具名","art":"prop.svg","width":4,"height":3,"walkThrough":false}`。width / height 为 1–12 的整数格；地毯等平面装饰可设置 walkThrough 为 true。SVG 使用透明背景、正面像素轮廓，表现顶面、侧面厚度、边缘高光与接触阴影；参考图只提取造型与配色，不嵌入原图，不调用整图生图。

SVG 须有数字 viewBox；仅允许 svg / g / path / rect / circle / ellipse / line / polyline / polygon / defs / clipPath / title / desc。每个形状直接设置颜色；禁止自写 style、脚本、SMIL 动画、文字、外链和图片。**道具支持真正的持续动画**：将动态部位画成 `g[data-part]`，在 prop.json 写入 `animations`，由宿主播放；水波、喷泉、旋转、闪烁等需求必须读 [局部循环动画](references/prop-animation.md)，不能用静态纹理替代或声称不支持动画。运行 `node <skill>/scripts/validate-prop.mjs output/prop.json`。可坐的沙发、椅子和长凳必须在 prop.json 添加 `seats:[{"x":50,"y":68}]`，坐点是道具边界内的百分比（5–95），落在坐垫表面，表示角色臀部落点；最多 8 个。用户要求“长椅可坐 3 人”，必须绘制三个座位并输出 3 个坐点（例如 x=20、50、80），各有独立占用状态。用户要求可踢的球，必须输出 `physics:{"kind":"kick","distance":4,"duration":700}`，宿主执行减速滚动、边界和家具碰撞。保留这些字段到项目模块，不可以只在描述承诺能力。不可坐道具用 `seats:[]`。不能仅在文字里声称可坐。宿主负责预览、磁吸摆放、复制、碰撞、坐下与实时共享；完成素材不等于已摆放。交互创作界面由用户应用；@Bot 用户明确要求放入当前项目时，使用万物同步助手 scene 流程直接预览和应用，不重复确认。仅要求存背包时只保存。

烟花桶、彩纸筒、发光灯支持真正的点击触发。在 prop.json 写入 `trigger:{"event":"click","effect":"fireworks","radius":3,"cooldown":8000,"duration":4000,"colors":["#efba55","#b491e1","#72bca6"]}`。effect 仅支持 fireworks / confetti / glow；范围 1–5 格，持续 1000–6000 毫秒，冷却不少于持续时间且不超过 60000 毫秒，颜色 1–4 个六位十六进制。用户明确要求放烟花等行为时必须输出对应 trigger；不可只画静态桶。宿主检查角色走近且停下，服务端统一冷却，所有项目成员播放同一时刻与随机种子的效果。素材 SVG 保存静态造型；持续动画由 `animations` 关键帧驱动，点击效果由 `trigger` 驱动，二者可以共存，严禁添加任意代码或脚本。交互创作界面生成完成自动进入当前项目道具背包，不自动改变布局；@Bot 按用户要求选择摆放或只保存；背包可重复取出，用户直接拖动，最终统一保存。

编辑已有项目时保留 modules 中所有 custom 道具的 id、svg、assetId、seats、physics、trigger、animations 和 walkThrough。用户手动摆放的位置可为小数格，不要重置。只修改请求涉及的模块，不能丢弃已有道具。生成新户型时要同时布置这些存量家具：读取 EXISTING_FURNITURE.json 和 PREVIOUS_OFFICE.json，沙发/地毯/茶几成组，会议室与办公室优先复用合适的桌椅和书架，绿植分散到房间与工位附近，烟花、泳池等放在可到达的公共活动区。不能把全部旧道具挤在地图底部或一条横排；不能自动取出背包中尚未摆放的道具。只换配色或材质时保留原摆放。

## 正面、可读的三块看板

公告、画布、Skills 三块看板不可缺失。它们是屏幕平行的矩形，不使用旋转、斜切、透视、倾斜纸条。普通场景每块至少宽 18%、高 16%，放在上方 32% 墙面内；有 floorPlan 时墙固定 9 行、板高至少 6 格，不重叠。不要把真实文字烘焙进底图；宿主 HTML 显示标题、公告摘要、画布/技能预览，点击可编辑或展开。文字由 React 或 textContent 输出，长内容裁切。画布与 Skills 的功能状态以宿主当前能力为准，不能伪造已同步内容。

默认沿用模板中 y=5.5%、height=24.5% 的加高看板，底边保持 30%，给地面和设备保留空间。三板顶边齐平，Skills 内展示三列、两行图标，更多技能在板内向下滚动；不要只截取前六项。标题与添加入口固定，技能名显示在图标下方、最多两行。自定义场景也要留够两行内容的高度，不能用缩小图标来塞满看板。

## 设备、成员与动作

设备由宿主根据真实绑定列表添加，不画死在场景里。生成母版时按人数留出足够、不重叠且可到达的工位；预留点不是虚假设备，也不锁定用户摆放。用户手动布局可自由重叠、贴墙或占用门口，不因碰撞阻止保存。新增设备和背包道具优先寻找空位，没有空位也可添加后自行移动；已有重叠不阻止继续添加。保留稳定 ID。主视觉中成员可辨认表情和动作，保留不同体型，不统一拉伸；比例参考人物画框约 100–130 世界单位、桌宽约 180–210。

成员与家具按脚底 Y 排深度。角色播放器只控制原地动作，宿主控制世界位移、导航和坐下。任务切换取消旧路径与回调。工作分身使用独立 ID/seed、彩色脚底标记与编号；状态由真实会话驱动，完成后庆祝、冒烟退场，本体保留。坐下玩耍与持续随机庆祝独立于工作池。

## 整洁与自由扩展

设备区＋按用途安排的休闲和活动区域，不在每台电脑旁添加独立座椅，不把所有机关同时塞进地图。保留沙发坐下、墙树避障、弹簧、飞毯、滑梯、烟花等扩展能力，按需读 [道具与机关契约](references/playground-props.md) 与 [运行契约](references/runtime-contract.md)。当前模块清单是宿主支持的起点；扩展新种类时需同步渲染、校验、碰撞和交互，不能只写一个未知 kind。

受控动画机关不等于完整物理引擎。保存未摆出的玩家道具而非删除，旧布局迁移只执行一次，不清空 localStorage。电脑、公告、画布、Skills 与已有内容始终保留。

## 验证与交付

校验模块在格子内、可行走区域连通、三板正面可读；测试不同设备数量、添加设备、导航到电脑/沙发、分身和深度关系。修改后的公告要立即在场景上显示。用浏览器验证正常与窄窗口，检查实际生成的主题区别，运行相关构建和测试。提供可打开页面/素材和截图。

同步 Claude/Codex 时检查项目及个人技能目录，保留各目录的附加文件。`assets/starter/` 是兼容旧独立演示的资源，不能用其中旧场景替代万物 AI 的 pixel-grid 契约。


## @Bot 与画布入口

@Bot 场景操作使用 wanwu-skills-sync 的 references/scene-workflow.md。支持 prop / character / office / action、只存背包、已有道具取出、自动尺寸与空位、按画布 ID/准确名字绑定入口。用户要求整理已有办公室时可用 scene-prepare --kind office --layout auto，读取母版后继续设计；保留所有已有道具的 canvasId。放不下时使用结构化 question 接口让用户选择存背包或调整布局，不能只输出文本选项，也不能把发公屏当成背包保存。
