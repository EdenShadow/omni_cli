# 户型、门洞与人数

当用户描述房间、隔墙、玻璃门、老板办公室、会议室、人数、横长或纵深时，输出真实 `floorPlan`，不能只画几根装饰线。先读宿主提供的 `FLOOR_PLAN_BRIEF.json`、`PREVIOUS_OFFICE.json` 和已规划的 `output/office.json`。母版已按人数安排工位、房间和公共通道；在其基础上设计配色和陈设，不要重新换回无房间模板。

独立使用可先规划，再调整主题：

```sh
node <skill>/scripts/plan-office.mjs assets/pixel-project.json output/office.json "木头墙，2个老板办公室、1个会议室，其中一个办公室较大，容纳30人"
node <skill>/scripts/validate-office.mjs output/office.json
node <skill>/scripts/render-project-scene.mjs output/office.json output/background.svg
```

## 数据格式

保持 schemaVersion 2、renderMode pixel-grid。新增可选字段：

```json
{
  "floorPlan": {
    "version": 1,
    "capacity": 30,
    "shape": "balanced",
    "wallRows": 9,
    "wallHeight": 1.15,
    "entry": {"x": 50, "y": 61},
    "rooms": [
      {"id": "meeting-1", "name": "会议室", "kind": "meeting",
       "x": 58, "y": 12, "width": 16, "height": 11,
       "material": "wood",
       "doors": [{"side": "left", "offset": 3.5, "width": 4, "material": "glass"}]}
    ]
  }
}
```

此片段只是字段示例，不是完整可发布场景。房间、门、入口使用**格子坐标**；deviceZones / walkable / boards 仍为百分比。门 offset 是沿对应墙边从左或上开始的距离。墙和门材质分别支持 glass / wood / solid。房间 kind 为 meeting / office / lounge，名称用用户的语言，仅作为编辑数据，不绘制到场景。房间最小 9×9 格，不能重叠；墙体可直接贴地图左、右、下边缘（x=0、x+width=columns、y+height=rows），不必为外侧保留一圈空地。顶部墙体不得遮挡看板（y 至少 wallRows+wallHeight）。每间 1–4 个门；门洞至少宽 4 格，离墙角至少 1 格。门必须朝向可行走公共走廊，不可开向地图外侧，每个房间从入口可达。

墙由 perimeter 自动生成并在门处断开。门有材质门扇与开启弧线，开口始终可通行，不需要绘制 wall 模块盖住门。不要把门当成必须点开才能通行的交互道具。家具、工位和隔墙不能占用门前后的空间。

## 面积、朝向和容量

columns 32–128、rows 24–128。每格素材基础 40 像素。默认优先保持当前母版的 columns，把新增房间和工位向下排列、增加 rows；只有用户明确要求横向加宽，或原宽度在最大纵深下仍无法容纳时才加宽。宿主 100% 会自动适配窗口可用宽度，默认只需上下滚动；放大可横向滚动，“户型总览”可看全局。不要通过压缩家具格数塞进更多工位。

- “比较长 / 横向”：shape wide，columns / rows 至少 1.7。
- “比较高 / 纵深 / 往下延伸”：shape deep，rows / columns 至少 1.3。指地图纵深；“挑高”才增大 wallHeight（0.5–3 格，默认 1.15）。
- “其中一个办公室更大”：该办公室面积比另一个至少大 30%。
- “容纳 30 人”：capacity 至少 30，deviceZones 至少 30 个独立工位，横向/纵向合理分组留通道，不能靠缩小家具塞进去。工位的占地相对锚点是 x-3.4、y-3.3、宽6.8、高5.5格；前方3.2格必须可达。建议锚点间距至少8格。
- 生成母版最多 12 个房间，1–100 个预留工位。生成时不能容纳就扩图或调整设计，不能靠重叠冒充容量。用户后续手动摆放则允许重叠、贴墙及占用门口；额外设备优先寻找空位，没有空位仍可添加后手动调整。

顶部看板墙在数据中固定 9 行，walkable 从第 10 行附近开始。三块板 y=1.5/rows*100、高6.5/rows*100，宽沿用原比例；不可沿用普通场景“高24.5%”将纵深地图大半屏变成墙。宿主单独显示顶部看板墙，公告、画布和 Skills 的显示高度不随地图行列数变化。保留开放办公区、通道与休闲区，会议室可放会议桌，老板办公室可布置会客沙发。

默认让外围房间隔墙接到场景边缘，门朝内部走廊，不要生成四周都留窄缝的悬空房间盒子。禁止在底图或家具上烘焙姓名、房间名、材质说明、预留工位等文字（也不能用路径拼字）；不要生成房间名牌或不可移除的悬浮说明。房间名称保留在 JSON 数据，实际公告文字和设备名称交给宿主。

新户型要把已摆出的存量家具一起重新布置，先读 EXISTING_FURNITURE.json 清单和 PREVIOUS_OFFICE.json。优先复用桌椅布置会议室和办公室，保持沙发/茶几/地毯组合，书柜与绿植分散安排，泳池、烟花等互动道具放到公共活动区。禁止把全部旧道具堆到最下方、排成底部一条或静默移回背包；背包里未摆出的资产不自动取出。保留所有 custom 道具 ID、尺寸、名字、SVG、assetId、座位、物理、触发、动画和 walkThrough 属性，只修改位置；发布前会核验存量道具是否丢失或被改坏。未改户型、仅换颜色或材质时不重排用户布置。不要创建虚假设备或成员；预留工位只是占地提示，设备仍来自账号真实绑定，加入后显示真实电脑。

## 必须验证

运行 validate-office.mjs。它会检查房间/门洞、人数、工位占地和从入口到门内外的连通性，拒绝封死房间、家具堵门和重叠工位。失败必须修好再交付。生成完成是预览，用户确认使用后才原子更新项目场景和设备位置，并广播给成员。

上述通路检查用于 AI 生成交付。用户的手动布局按其摆放位置保存，不用这些检查拦截重叠、占用预留点、贴墙或挡门，也不弹出强制调整提示。宿主仍校验数据格式、素材来源、权限和并发版本，保存后全团队看到同一份布局。
