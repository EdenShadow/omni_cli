# 上方三板与墙面的自由设计

顶部也是场景美术的一部分。保留 `boards` 的位置、宽度、内容和全部功能，可以设计背墙、灯具、边框、面板底色和装饰底纹。春节春联、灯笼、圣诞松枝与灯串只是示例，不限制主题。静态装饰默认静止。

- 背墙：`appearance.wallSvg`，建议 viewBox `0 0 1600 320`，宿主铺满上方墙面。根据现有 boards.x / width 计算空隙，把春联、挂件放在板间或顶部安全带，不能被面板遮住。允许静态安全 `text/tspan` 写春联等装饰文字；不能伪造公告、聊天和技能内容。
- 面板：`appearance.boards` 的 `announcement`（公告）、`canvas`（中间团队聊天，兼容字段名）、`skills`（右侧画布/Skills 切换）可各自设置 `background` / `foreground` / `muted` / `border` / `accent`，全部六位十六进制颜色；可选 `backgroundSvg` 绘制边角或低对比底纹。
- SVG 沿用安全静态形状契约，无图片、外链、脚本、style、SMIL；每份不超过 160 KB。背景 SVG 不接收鼠标，不覆盖真实控件。
- 不改变三个区域的尺寸、间距、padding、标题与按钮；高对比花纹留在边缘，文字后面保持安静。用户指定的公告 HTML 仍保留其内容和设计，场景主题不擅自改写正文。默认紧凑公告可透出面板底纹；自定义不透明公告需要另行编辑其 compactHtml。
- 明确给出背景色，按该背景选正文、次级文字和按钮颜色。深色应用里也可以做奶油白面板；验收深浅主题，不能依赖全局主题恰巧可读。宿主按面板配色生成控件底色与可读文字；设计验收应包含表情回应、BOT 标记、消息菜单、悬停、选中及键盘焦点，不能只看静态面板。底纹避免在正文及按钮下方出现强烈明暗变化。

例如（仅展示结构，实际要结合空间设计）：
```json
{"appearance":{"boards":{"canvas":{"background":"#163D36","foreground":"#F6F0DF","muted":"#BCD1C6","border":"#B9985B","accent":"#F3D897","backgroundSvg":"<svg viewBox=\"0 0 480 280\"><path d=\"M8 32V8H32 M448 8H472V32\" fill=\"none\" stroke=\"#B9985B\" stroke-width=\"2\"/></svg>"}}}}
```

这是新增的宿主能力，需要包含此契约的客户端与服务端。旧版若拒绝 `appearance.boards`，不要声称已经应用；可先展示独立预览、保留原场景并明确需要更新宿主。仅墙面换色/几何装饰的旧能力仍可用。验收必须在真实宿主里看到三板背景和后墙，并实测公告、聊天展开、Skills/画布切换及鼠标操作。
