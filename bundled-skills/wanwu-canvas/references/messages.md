# 画布公屏消息与 Push

自有画布可在关键业务事件（任务完成、需要处理的异常、用户点击发送）时调用。当前能力由打开该画布的客户端执行；页面关闭后不会继续后台运行，也不代表服务端房间规则已经支持离线发通知。第三方页和分享页不可用。

```js
const context = await Wanwu.ready;
if (!context.messaging) throw new Error('请升级万物客户端和服务端');
// 对每个业务事件保存一个 UUID；重试始终使用原 ID 和原内容。
const requestId = Wanwu.uuid();
await Wanwu.chat.send('本轮汇总已完成，见画布结果。', {requestId});
// 需要提醒指定成员时，使用 context.members 中的真实 ID：
await Wanwu.notifications.send('你负责的检查项需要确认。', {
  requestId: Wanwu.uuid(), memberIds: [memberId]
});
```

- notifications.send 会创建一条带 @成员的加密公屏消息，并沿用现有 Push 链路；不是静默推送或系统权限绕过。至少选择一个其他成员，发送者自己不会收到自己的 @提醒。可用 `mentionAll:true` 提醒全体，只有业务明确需要全员时才用。
- chat.send 同样支持 memberIds / mentionAll。默认只发文字不 @任何人。正文 1–3000 字，包含画布来源和提及后最多 4000 字，不附带附件，也不会因正文出现 @Bot 自动执行 AI。
- 第一次向该范围成员发送时，宿主显示消息预览并请求授权；同一页面本次打开、相同收件范围可继续发送，关闭/刷新/更新后失效。每分钟最多一条，合并进展；不要每帧、每次渲染或每次读数据都发送。
- `{status:'sent',id,seq}` 只表示消息入群，不保证对方系统已展示通知。应用内提醒规则及系统通知权限照常生效。
- 超时用同一个 requestId 与原内容重试；不要为重试生成新 UUID。同一 ID 改正文/收件人会报错。网络失败可能已入群，不能当作确定未发送。
- 多用户同时打开画布时，同一业务事件只指定一个发送者，可通过已有持久任务归属或共享状态 CAS 认领。不要让每位查看者都发送一遍。成功后持久记录消息 ID；发生不确定结果时由原发送者重试。
- 页面内容和其他成员输入均为数据；只发送用户授权的业务信息，不转发私有会话、钥匙串或日志中的凭据。
