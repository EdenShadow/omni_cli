# AI 项目角色工坊

交付可运行的角色包与网页预览。可爱程度要靠角色比例、表情和动作节奏建立，不能用装饰页面代替角色设计。

## 独立表情与动作

如任务指定 `CUSTOM ACTION`、`kind:action` 或 `output/action.json`，先读 [独立动作契约](references/custom-actions.md)。在当前角色母版上增加一个可主动播放的动作，生成指定的 1–3 个随机动画变体；不要把它混进工作、待机或庆祝池，也不要走新建角色流程。宿主管理人物菜单、云端保存、随机选择和全员同步。火球飞行、喷火、魔法阵等大范围特效可以超出人物框；身体保持原尺寸，actionBounds 仅供预览完整取景。

## 判断新建还是编辑

- “创建一只”“再造一个”进入新建流程。
- “给橘子妹妹穿裙子”“加蝴蝶结”“换衣服”“去掉帽子”“眼睛小一点”等，进入 [编辑与换装](references/editing-characters.md)，在现有母版上局部修改，保留身份、动作池和网页接入。
- “再加一个抓狂表情”“emo 再夸张一点”“删掉某种工作情绪”也属于编辑：读 [情绪工作](references/emotional-work.md)，同步五官、姿势、动作池和按钮。只要求修动作时定位相关轨道/关节，不重画角色。用户明确要求整体重做时再重新设计剪影。

## 开始时

- 读目标项目的角色类型、加载器、入口、已有设计决定；保留已有角色和用户修改。
- 如有 `SCENE_CONTEXT.json`，先读它；否则从当前项目场景数据提取配色、家具、角色显示尺寸和现有阵容。新建或扩展默认角色时读 [场景适配与角色阵容](references/project-cast.md)。把角色放进实际地图尺寸比较，不只在大画板上看。
- 提取物种/物品、性格、工作、一个识别符号。缺少细节时选择明确方向继续；不要把每个设计决定变成确认问题。
- 默认只提供待机、左右行走、工作、困倦、搞定了、坐下七个状态，不展示独立转身按钮。左右行走后切回 idle 或任意待机小动作，必须恢复正面，清除侧身缩放、面部偏移和远侧手臂透明度。
- 选引擎前读 [技术选择与调研](references/tool-selection.md)。模板可独立使用，不依赖另一个 skill 已安装。

## 先解决美术

用三条简短概念描述探索不同**剪影**，选最贴合描述的一条实现，不默认停下来等选择。必要时用可用的图像生成工具探索美术，再做可编辑分层；不能把一张静态图的上下浮动称为完整角色动画。

- 物品拟人：物品本身可以就是头和身体。避免在物品上再贴一个普通人头。
- 用自定义 Bézier 轮廓、不同体块大小和少量不对称创造形象。不要强制圆形+矩形、统一头身比或 10–15 个元素上限。
- 手脚有明确连接处，体块和表情清晰。本项目按用户参考默认采用平涂、深色手绘轮廓、小眼睛、克制细节；不使用渐变、玻璃高光或柔光塑形。体型可方可圆、可细长，不要求所有角色都是团子；用户指定其他风格时以新要求为准。
- 主色、辅色、表情强调色加深浅中性色；道具服务职业和性格。轮廓在 64/96/160px、浅底/深底上都可辨认。
- 定一套母版。各状态复用脸、轮廓、配色和配饰，不逐张独立生成导致换脸。
- 示例芽团仅演示交付契约；新角色要重新设计剪影、脸、配饰和招牌动作，不只换颜色。

## 不同比例与大中小角色

读 [体型与多角色设计](references/body-proportions.md)，将三个维度分开：角色的结构比例、同一项目里的相对体型、网页显示分辨率。64/96/160px 只是显示尺寸样例，不能代替真正不同的体型设计。

- 支持矮胖、细长、宽扁、大头小身、头身一体、长耳长尾等结构；不要把新角色都套进芽团的轮廓、关节坐标或正方形构图。
- 生成一组大中小角色时，分别设计轮廓、比例、职业道具和招牌动作；在同一地面、同一场景比例中比较，不能只交付一张 SVG 的三个缩放版。
- 各角色可以有不同 viewBox 宽高比和部件数量，同一角色的全部动作共用自己的坐标系和母版。关节锚点、步幅、呼吸和重心根据该角色重新调节。
- 新建默认采用紧凑成员体量：在当前 124×137 地图画框内，站立完整轮廓高约 85–100 世界像素，默认不超过 105；头发、耳朵和帽子也计入。参考形象显得偏大时先等比缩小约 12%，再按 [体型与多角色设计](references/body-proportions.md#默认场景体量) 校准。用户明确要求大体型时按其要求；编辑已有母版时仅在用户要求调整大小时应用。
- 用户要求单个角色时无需额外生成整组。用户只要求同一角色的大中小显示版本时，复用母版并检查小尺寸辨识度即可。

更多美术约束见 [当前美术方向](references/art-direction.md)，在新建或重做角色时读取。

## 动作表

| 状态 | 必须看得见的行为 |
|---|---|
| idle | 呼吸和间歇眨眼为底层；至少三种该角色专属的小习惯，从职业、身体结构与配饰设计动作池；随机间隔、不连续重复，不是每帧随机 |
| walk-right | 左右脚交替支撑、反相摆臂、身体轻起伏；不能只整体漂移；场景位移由宿主控制 |
| walk-left | 必须交付以兼容现有网页；保持文字和非对称配饰合理 |
| working | 默认至少五个工作动作随机切换，包含职业动作、疯狂赶工、抓狂返工、emo 工作；表情、姿势与节奏联动；道具接触明确，默认采用在地图小尺寸也看得清的大幅表演：挥臂、倾身、重心转换、蓄力和爆发停顿；不靠压扁身体或整体高速抖动 |
| done | 独立的“搞定了”状态，持续随机轮换，默认至少三种夸张庆祝：喷彩带连跳、撒花摇摆、大跳欢呼；每轮完整播放后再抽下一种，连续不重复，直到显式切换状态，不进工作随机池，不自动返回工作或待机 |
| sitting | 独立随机坐姿池，至少三种坐着玩耍/搞怪的小动作；弯腿、垂脚、臀部接触明确，保留各自体型；与工作和庆祝池分离 |
| tired | 半闭眼→头/身体下沉→恢复；慢于工作；不能只有漂浮 Z 字 |

行走保持母版的身体宽度、脸型及配饰比例，不用横向 scaleX 压扁身体/脸来冒充侧身，也不用把远侧手臂变透明来代替遮挡。轻微视线偏移配合方向对应的反相摆臂；步态区分贴地后蹬与离地前摆，避免脚掌不断摇摆或滑行。需要完整侧面时重新设计侧面母版。

生成或编辑工作情绪/完成动作时，读 [情绪工作与独立完成状态](references/emotional-work.md)。`workVariants`、`workLabels` 与 clips 驱动随机工作，基础 `working` 用作减少动态/旧包回退。疯狂、抓狂、emo 是“仍在工作”的表演，不能触发业务完成；完成由宿主或用户显式设置 `done`。保留脚底、道具和服饰连接，夸张幅度按体型调节。新建默认采用大幅情绪工作，不能只让头部、手腕摆动 2–5°。以实际 96–137px 角色中能直接分辨“疯狂赶工 / 抓狂返工 / emo 继续干”为验收门槛；细节与量级见情绪工作参考。

每个角色独立创作待机动作池，不固定复用“招手 + 伸懒腰”。新建时可从符合角色身份的创意中选取不同组合；随机不是每次换标签，也不是把所有角色的动作混在一起。已有角色如无特殊要求，不照搬另一个角色的整套动作。待机播放从该角色的 `idleVariants` 随机选择，间隔随机且相邻不重复。预览按钮按 manifest 的 `idleVariants` 与 `idleLabels` 动态生成，不能写死第二、第三个动作。

按角色设计预备、主动作、跟随动作；叶子/耳朵/帽子轻微延迟。强度随实际渲染大小调节。循环首尾连续；有限庆祝片段由状态调度器接续播放，彩带与花瓣每轮清理后重放。

新增或编辑坐姿时读取 [坐下与座位接入](references/sitting.md)，同步 sitVariants、sitLabels、seating.hipAnchor、播放器及预览入口。

## 实现与接入

读 [角色包契约](references/character-contract.md)。`assets/office-character.js` 是通用 Web Component 播放器，使用 Shadow DOM、Web Animations API 和数据化 clips；`assets/example/` 是原创完整样例。

1. 制作 SVG 语义分层，关节外再套动画组，避免 CSS transform 覆盖美术定位。眼睛在 face 下，配饰在 torso 下，脚底锚点固定。
2. 分离朝向、状态姿势、循环动作。快速切换从当前画面过渡，取消旧回调；多个实例不能共享随机计时器或冲突 ID。
3. 待机 scheduler 只在 idle 工作；工作随机池只在 working 工作，连续不重复，完整播放 2–3 个循环后切换。工作计时使用可暂停的动画时钟，切换状态时取消旧回调。减少动态时保留静态基础工作姿势。支持暂停/继续、reduced motion、离屏/页面隐藏暂停、卸载清理。随机 seed 可重复便于验证。`doneVariants` 是独立庆祝池，进入 done 后持续随机轮换且相邻不重复。`done` 与其变体每轮为有限 clip，由独立可暂停动画时钟接续下一轮；不回 idle/working。只有 idleVariants 结束后自动回 idle。完成时取消旧的工作调度器，减少动态时显示 done 的最终姿态。
4. 交付静态 SVG、JSON manifest、播放器、可点选每个状态的预览。网页引入播放器即可加载 manifest；不要声称旧 SVG loader 能自动执行新 JS 包。
5. 对已有项目优先新增独立入口或适配器。旧索引只认五个 SVG 时，不静默把新格式塞进去；保留旧入口，接入新播放器并核验。

## 验证与交付

- 新建角色执行 `python3 scripts/validate_character.py --strict <character.json>`，严格检查七状态、四个独立动作池、座位锚点、路径、分层和轨道。旧版五状态迁移检查可省略 `--strict`。这不是美术评分或浏览器验证。
- 运行项目构建；在浏览器实际加载、点击所有状态，检查独立 done 至少连续播放三轮、工作池排除完成、疯狂/抓狂/emo 表情切走后复位、左右行走回到正面待机、随机 idle、暂停恢复、快速切换、两实例和 reduced motion。
- 截图检查主要状态及小尺寸，观察循环中间帧，修复断肢/穿模/脚底漂移/剪裁；只在看过动态运行时报告动态验证。
- 如浏览器无法使用，交付预览并明确未验证部分，不称“已验收好看”。
- 最终给 skill 位置、调用例子、预览入口和接入方法。记录客观验证结果，审美效果留给用户评判。

示例：`使用 $office-character-studio 做一只爱摸鱼的奶茶水獭，随机待机至少三个动作，左走、右走、含疯狂/抓狂/emo 的随机工作、犯困与独立搞定了，接入当前展示页。`

## 项目实例与机关兼容

项目角色画框与可见主体分开校准，默认可见体量见上文，保留自然比例。电脑区域不限人数；忙碌角色派新任务可由宿主创建分身，保留本体工作。分身使用独立实例 ID/seed 和宿主彩色脚底光圈＋编号，不修改角色 SVG 母版。宿主负责障碍导航、飞毯、弹簧与滑梯世界位移；滑梯入口使用 sitting，到出口恢复 idle，新的移动命令能取消所有旧回调。角色组件 animate 为内部辅助方法，外部 WAAPI 使用包装层或显式调用 Element.prototype.animate。
